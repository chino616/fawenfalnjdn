# Isolated automatic runs

本协议由 Master Skill 在用户要求进入或切换自动模式时读取。自动运行只生成**候选结果**；
正式项目中的代码、数据、报告、Gate 和主线进度在用户审核并批准导入前保持原状。
本协议用于真实的 `physics_onboarding` 或 `existing_dataset` 工作；`skill_debug`
仍按其只读或逐项写入规则执行。

## 两档自动程度

| 模式 | 候选目录内自动完成 | 暂停条件 |
|---|---|---|
| `low_auto`（低自动） | 收集证据、实现已确定的路线、运行检查、修复不改变物理含义的技术问题 | 需要选择物理路线、每阶段关键审核点、超出计划范围或检查无法通过 |
| `high_auto`（高自动） | 在目标和资料明确时连续完成所选阶段；按事先列出的证据优先级处理无冲突的细节，自动检查与有限次修复 | 材料冲突或物理含义不明确、无法保证隔离、超出计划范围、检查持续失败、需要改变科学主张 |

两档均可在隔离目录内继续探索下一阶段，**不得把候选检查通过写成正式 Human Gate
`APPROVED`**。低自动在关键点请用户检查候选；高自动不逐阶段等待用户。需要比较不同
物理路线时，高自动可在计划允许的数量内生成并列候选，但不得把其中一个未经用户
接受的路线写成正式科学结论。

## 先介绍模式，再让用户选择

任务范围已能说明、准备开始或恢复阶段工作时，Master 用普通中文**一次**介绍运行
方式并展示选择；用户已经明确指定模式时，简短确认其选择并进入只读计划核查。
不要在每次答疑后重复菜单。用户随时可以回复“查看运行方式”重新查看。

按 `_shared.md` 的分块版式展示：状态块说明当前仍为逐步确认或尚未选模式；
“本次回答或进展”块介绍低自动、高自动和逐步确认各会怎样运行；“需要你做什么”
块列出 `选择低自动｜选择高自动｜保持逐步确认`；“你还可以”块可提供
查看当前正式进度。低/高自动的科学与文件边界须在后续计划中进一步说明。

根据当前材料可以推荐其中一档并说明原因，但不能代替用户选择。选择低/高自动
**只生成下一步的警告和计划**，不等于启用，不创建独立目录；随后仍须按下节
用带 `plan_id` 的准确回复启用。选择逐步确认则保持现有正式工作流。

## 安全进入：先展示计划，再显式启用

用户只说“自动运行”而未选择程度时，先说明两档区别并请其选择；不默认进入高自动。
用户说“进入/切换低自动”或“进入/切换高自动”时，只启动只读准备，不创建目录。
Master 先核对当前正式进度和输入，再按
`templates/auto/AUTO_RUN_PLAN_TEMPLATE.yaml` 展示一份带唯一 `plan_id` 的计划。
模板只提供结构，不预填某实验的物理选择。计划至少写清：

- 实验、dataset、目标科学声明、起止阶段与当前断点；高自动要求这些身份和范围
  已明确。若仍有多个 dataset 候选，高自动不可启用。
- 按顺序列出本次要执行的模块编号和中文名称；列表不能为空，且逐模块报告
  要求不能在计划中关闭。
- 独立运行目录的绝对路径、要复制的材料、原项目的指纹、预计生成的结果、时间/
  空间/修复次数上限，以及退出或恢复方式。上限必须是明确的正数；未确定时
  继续只读准备，不启用自动运行。
- 低/高自动会自行处理什么、哪些情况必停；高自动采用的证据优先级及允许的
  候选分支数。不得用“全部问题自动处理”替代具体边界。
- 明示警告：自动结果可能存在物理或代码错误；自动阶段只改隔离副本，**不会改动
  原项目**；导入原项目需要单独审核和批准。

只有用户在看过该计划后准确回复 `启用低自动 <plan_id>` 或
`启用高自动 <plan_id>`，才允许创建并写入该计划列出的隔离目录。普通的“自动做”、
“可以”或讨论模式的消息都不构成启用。启用授权只覆盖这一 `run_id` 的隔离目录，
不覆盖原项目、外部服务或其他运行目录；计划内容或原项目指纹变化后，先停下并
重新展示计划。`plan_id` 必须绑定计划全文和源指纹，不能重复利用旧口令。
计算编号时对计划内容作稳定序列化并排除 `plan_id` 字段；启用消息引用写入
`AUTO_RUN_LOG.yaml`，不回填改变已经批准的计划。

## 独立目录与运行边界

目录位于**项目目录之外、已允许写入的同一工作区内**：

```text
<workspace_root>/.experiment-auto-runs/<run_id>/
  AUTO_RUN_PLAN.yaml
  AUTO_RUN_LOG.yaml
  MIGRATION_PROGRESS.md
  snapshot/                 # 可运行的项目副本，保留原项目相对路径
  review/module_reports/    # 每个已执行模块的候选报告
  review/                   # 最终差异、检查报告和导入计划
```

使用独立的文件副本，不用会改动原项目 Git 元数据的 worktree，也不复用原项目
虚拟环境中的可写目录。复制执行所需的项目文件并保持相对目录结构。
不得把 `backup/**`、其他自动运行目录、缓存或虚拟环境当作物理材料复制或扫描。
不得以指向原项目的可写符号链接代替副本。运行前检查解析后的所有可写路径均位于
本次目录内；工作目录、临时文件、Python 缓存、图表及测试输出也指向本次目录。
不得在自动阶段调用会向原项目、外部应用或网络写入的命令。若无法确认写入隔离，
停止自动运行。原项目在这一阶段只读。

自动修复仅限当前计划的科学定义和目标范围内；每次修复后重跑受影响检查。
不得通过改已批准数值、删除失败检查、放宽容差或改参考结果制造通过。
达到计划中的修复次数、时间或空间上限时停止，并保留候选现场。

隔离进度文件只记录候选断点和已运行检查；`AUTO_RUN_LOG.yaml` 先记录原始启用
消息引用，再追加记录时间、
执行动作、受影响的隔离路径、候选依据、检查结果、用户在低自动中作出的反馈、
停止或切换原因。二者均不得充当正式批准或正式进度。

## 每个模块完成后留下报告

启用计划中的 `module_sequence` 定义本次逐个执行的模块：P01–P10 各算一个模块；
若计划包含 onboarding 工作，也须把其阶段列为独立模块。低自动和高自动都遵守
同一报告要求，不能只在整次自动运行结束时给一份总报告。

每完成一个模块的候选工作及其检查，**先**按
`templates/auto/AUTO_MODULE_REPORT_TEMPLATE.md` 在本次隔离目录的
`review/module_reports/<module_id>_r<revision>.md` 写报告。模块编号须可安全用于
文件名；报告用普通中文说明：本模块目标、
实际做了什么、哪些结果已完成并通过什么检查、哪些仍未完成或有不确定性、
下一模块要做什么及进入条件；附输入依据、候选文件、检查结果和本次计划编号。
若模块受阻或运行中断，也写明 `BLOCKED` 或 `PARTIAL` 的现场报告，不能写成完成。
同一模块重做时保留旧版并增加修订号，不覆盖已有报告。写报告前先分配唯一的
日志事件编号，使报告可以引用稍后登记的同一事件。

报告写入并核对后，把报告的相对路径、SHA-256、状态和对应日志事件写入隔离
`AUTO_RUN_LOG.yaml` 与候选 `MIGRATION_PROGRESS.md`。若报告或登记失败，不把模块
标记为完成，也不进入下一模块。**每份已登记的模块报告，无论结果为
`COMPLETE`、`PARTIAL` 还是 `BLOCKED`，都立即向用户发送一次**按 `_shared.md`
四块版式编排的进度回复。状态块明确结果和隔离候选身份；进展块用普通中文
概括“做了什么、完成了什么、尚未完成什么、下一模块计划或停止原因”，并直接
给出指向已存在报告文件的可点击本地 Markdown 链接，例如
`[查看 P04 模块报告](<绝对路径/P04_r1.md>)`。先核对该绝对路径确实存在并与
登记指纹一致；不能只给相对路径、文件名、日志编号或“稍后提供报告”的承诺。
如果用户要求在对话内查看全文，直接展示报告内容。行动块说明是否需要审核或
自动继续；最后保留“审查当前物理内容”入口。高自动只有在报告已发给用户且
结果允许继续时才可按计划进入下一模块；低自动在计划规定的审核点等待用户。
`PARTIAL/BLOCKED` 时说明当前阻断和恢复条件，不把下一模块写成已经开始。
无下一模块时说明进入候选总体审核，不假称正式集成完成。模块尚在运行、报告
尚未生成时，进度回复明确写“本模块报告尚未生成”，不伪造可查看的链接。

候选模块报告只是过程追踪，不是正式 Phase 报告、Physics Decision 或 Human Gate。
最终导入时逐份核对这些报告与实际差异；正式报告和 Gate 仍按审核后的导入计划
写入原项目。

恢复运行时核对启用消息、计划、源指纹和隔离目录；任何一项无法核对就停止。
自动模式表示同一次工作可连续推进多个候选阶段，不表示有未声明的后台任务。
如果执行环境中断，记录候选断点；用户回来后按 `run_id` 定位并复核后继续。
多个隔离运行并存时请用户选择 `run_id`，不得把其中一个当成原项目当前进度。

## 运行中随时审查物理内容

低/高自动运行时，每次向用户报告阶段开始、阶段切换或有意义的检查结果，都按
`migration_blocks_v1` 输出：状态块写明低/高自动、当前候选阶段和“原项目未改”；
进展块用一两句说明**当前处理的物理问题及检查结果**；行动块写“无需操作，
自动继续”，若实际已暂停则说明待办；“你还可以”块保留
`审查当前物理内容｜查看候选进度｜调整自动程度｜暂停自动`。
普通进度提示不要求用户回复，高自动可继续运行。

用户回复“审查当前物理内容”时，在可中断的安全点暂停新的候选步骤，记录当前
阶段、步骤和 `review_pending`。先回答用户当轮的问题，再展示本阶段实际使用的
模型或公式、输入数值与单位、资料来源、关键假设与不确定性、尚存的其他解释、
已完成的检查，以及这项选择会影响什么；只展示当前阶段需要审核的内容，详细
证据提供链接。低自动到达计划中的审核点时也使用同一套说明。

审查期间不继续自动执行。用户可回复“继续自动”按原模式恢复，或提出修改、
降低自动程度、退出自动；恢复前重新核对计划和源指纹。修改仍在原计划范围内时
先记录候选反馈再继续，扩大物理或文件范围时重新展示计划与警告。审查对话
本身不批准正式 Physics Gate，也不授权把候选导入原项目。
审查回复和“继续自动”后的第一条进度回复都重新按 `_shared.md` 的四块版式
生成，不沿用审查中可能出现的问答格式。
用户在审查或旁支后只说“返回主线”或“继续迁移”时，也按四块版式展示当前
候选断点和待办；这不是“继续自动”，不得据此恢复已暂停的候选执行。

## 模式切换

- `降低为低自动`：立即停止高自动的后续自主选择，保留当前候选；低自动只在
  原计划的更窄范围内继续。已生成的候选不得因此变成批准结果。
- `暂停自动`：立即停止新操作并保留当前计划；恢复前重新核对源指纹和边界。
- `退出自动`：立即撤销剩余的隔离运行授权并保留目录供检查；重新进入需要新计划
  和新的准确启用回复。两者都不自动导入。
- 从低自动升为高自动、扩大阶段/材料/写入范围，或更换 dataset/科学声明：
  重新进行安全进入，展示新警告与新 `plan_id`，获得对应启用回复后才执行。

## 审核与导入原项目

候选完成后先展示：实际物理路线与不确定性、运行过的检查及失败项、与原项目的
逐文件差异、要新增/修改/删除的准确原项目路径、依赖关系、备份和恢复办法。
用户可以继续让隔离目录修改，或只查看差异；候选完成本身不改变正式 Gate。

`promotion_id` 必须绑定实际差异、科学结论、原项目基线指纹、目的路径及动作；
这些内容变化就重新生成编号和审核计划。只有在上述内容已展示且不存在未决科学
选择后，用户准确回复
`批准导入 <promotion_id>` 才允许导入。该口令明确同时表示：接受所列科学结论，
并授权将所列文件按相对路径写入原项目。Master 分别写入 Physics Decision 和
Write Authorization 记录；任何未列路径、动作或科学声明仍不在授权内。

导入前重新核对原项目文件与候选基线的指纹。若原项目已变化，停止并重新合并
候选，不覆盖新内容。按仓库备份规则保存将被修改的原文件，然后逐文件写入对应
路径；不得把整个自动运行目录搬进原项目。写入后在正式项目运行必要的检查，
记录正式 Gate 与进度。导入中断或检查失败时，按已展示的恢复计划回退，候选目录
保留供调查。自动运行目录的清理需要用户另行明确要求或事先列明的保留期策略。
