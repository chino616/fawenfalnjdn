# CEvNS 物理模块拆分与替换 Skill

## 使用目标与范围

先解释用户要改变的物理量，再回答哪些数据、参数、函数、适配器、调用方和缓存受影响。
“换源”不能只回答换一个 flux 文件；“换探测器”不能只回答改效率；“更模块化”不能只把长函数移动到另一个文件。
模块化完成的判据是：在保持接口契约时，替换该模块无需重写不相关物理层。

本 Skill 是项目内的工程审计、替换设计与实现辅助说明，不新增实验集成 Phase，不替代
[实验集成 Master](../cevns-experiment/SKILL.md)。只读答疑和设计不启动实验迁移、创建 dataset 或变更 Gate。
真正新增/迁移实验、改变物理模型或修改已有实验计算时，先按仓库 `AGENTS.md` 和 Master 确认适用范围及既有授权。
用户要求创建这份文档不等于要求立刻重构运行程序。

代码基线：2026-10-28 核对的 `260929Gitup1-CONUS-2/Gitup01`，以 COHERENT 三条路径为主要实证。
此处的代码事实不是新实验的物理输入，也不证明所有理论规范已经外部验证。
所有新通用接口在参考文档中标为 `PROPOSED`，不得对用户声称已经可以 import。

## 必须区分的四类信息

1. `CURRENT`：实际存在且在当前调用链执行的实现；用 `文件::符号` 定位，并核实调用方。
2. `DORMANT_OR_METADATA`：存在但不在本次路径执行的对象、常数表、公式字符串和兼容重导出。
3. `PROPOSED`：推荐的新边界/接口/参数化方案，当前不保证存在。
4. `UNVERIFIED_PHYSICS`：内部实现存在，但外部约定、来源、适用性或物理检验尚未闭合。

路径存在不等于运行时使用；目录名 `rates`、`kernels` 不等于内部所有函数实验无关。
YAML 能被读取不等于对应运行函数用该字段计算。表格文件存在不等于源加载器读取它。

## 实施方法

### 1. 确定替换量

从用户上下文判断是在改输入数值、模型、数值算法还是输出约定。
先做能独立进行的只读定位；仅对会改变物理含义且上下文不能确定的选择提问。
默认保留已接受的模型、现有实验行为和接口兼容性。

### 2. 建立物理到代码的映射

按 01 的模块 ID，记录：

```text
物理对象及公式 → 输入/单位/轴 → 输出/单位/轴
→ 参数真实来源 → 当前 文件::符号 → 直接调用方
→ 替换类型 → 连带失效结果 → 最小验证
```

拆开源形状/归一化、粒子身份/密度矩阵、核结构/探测器响应、核数/曝光、
物理能量边界/数值网格、反冲谱/重建谱、事件数/每 bin 宽度密度、振幅核 K/算符积分核 H。

使用 `rg` 搜索实际引用。排除 `backup/**`；不得借恢复副本填补活动代码或物理来源的缺失。
先用 02 定位，再复读实际函数。必要时用缩小网格追踪调用，但不得把小网格产物冒充精确物理基准。

### 3. 确定最小替换范围

沿用仓库分类：

| 分类 | 选择依据 |
| --- | --- |
| `REUSE` | 公式、粒子类别、单位、轴、边界和归一化约定都适用 |
| `CONFIG_ONLY` | 只有数值/数表变化，且已证明运行代码读取该配置 |
| `ADAPTER` | 核心物理适用，只需新源/靶/探测器接口转换或编排 |
| `SHARED_EXTENSION` | 共享算法需新增参数、源分量或轴，必须检查所有调用方 |
| `CORE_EXTENSION` | 振幅、匹配、核响应规范等物理核心改变 |
| `BLOCKED` | 必需物理资料或能力不足，不能用旧实验默认值填补 |

不要把“多个函数位于同一文件”当成必须整文件替换。不要把“公式一样”当成接口已经可复用。
新实验优先新增薄适配器，保留 COHERENT 原有源和探测器模型。

### 4. 检查跨层绑定

至少按场景核对：

- SNS 的 `mu/e/mub`、`muLine`、μ 衰变端点、通量插值和曝光基准；
- `NeutrinoState` 只知道 rho 的形状，能量值对齐与掩码切片需要显式处理；
- Cs/I 质量权重、单核质量、整台探测器质量与接受率各只乘一次；
- gamma PE response、CsI2017 确定性 PE 映射、Ar2020 高斯形式属于不同模型；
- Slow 和 Fast 对源、匹配、运动学、粒子响应与探测器的重复实现；
- Fast 存储与统计预测器对 dataset/source/bin 的固定假设；
- 参考公式中的权重是否真在代码出现，不能猜测已被 JSON 吸收。

### 5. 形成可审核的结果

回答中至少给出：物理变化、具体文件和符号、为什么要动、保持不变的层、下游结果和检查。
涉及实现时区分本次已改与建议后续改；沿实际依赖重算，不一律重做所有模块。
可使用以下替换记录格式，字段内容必须来自实际检查：

```text
change: 物理量/模型/数值方法
contract: 输入输出、单位、轴、边界、归一化 owner
current_owners: 文件::符号及调用方
classification: 既有分类
minimal_actions: 配置/新增适配/接口扩展/核心变更
unchanged_physics: 本次不变的物理模型
invalidated_outputs: 反冲谱/响应矩阵/H/统计等具体产物
verification: 对应物理不变量、回归与数值精度
known_limits: 本次仍不能宣称的能力
```
