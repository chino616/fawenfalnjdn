# Onboarding 数据溯源与补充闭环

本规范适用于所有实验的 onboarding 草稿、用户资料、Physics MD、配置和数据输出。
**每个实际采用的物理数值、数值数组、公式与处理选择都必须有可核对的依据；首次输出不是完成声明。**
来源身份以 P00 为权威，逐项提取与推导以 P01 为权威，未闭合项进入 P02，实际配置进入 P03。
本规范不新增科学批准状态，也不替代原有写入授权与 H0–H3。

## 1. 什么必须溯源

包括输入参数、物理常数、同位素组成、曝光、源谱节点/系数/配比、效率、响应数值表、
观测点、误差、协方差、分箱、benchmark 数值，以及插值、外推、裁剪、拼接、积分域、归一化和统计近似。
不能只溯源正文里的几个主要参数而遗漏数组、边界或代码默认值。

逐项区分以下依据：

| 类别 | 必须记录的内容 | 不能声称什么 |
|---|---|---|
| 原文/官方数据直接给出 | 来源版本、原始定位、数值/单位和实际核对范围 | 仅找到 DOI 或摘要不等于核对了数值表 |
| 二手材料转录 | 实际抄录材料及表/页；其引用的上游文献另列；上游是否核实 | 不能把二手转录直接标成原文已核 |
| 图像/向量数字化 | 原图版本/页/图、坐标标定、取点/误差条方法、单位、脚本与误差限制 | 数字化点不是作者原始数表；保留有物理意义的负值 |
| 项目推导/生成 | 公式或算法、全部输入 claim、单位换算、代码/版本、网格/边界及结果检查 | 生成结果不是文献直接测量值；输入缺口会传递到结果 |
| 用户指定的配置/近似 | 决定引用、具体选择、理由/影响及原值对照 | 用户接受近似不等于原文事实已核实 |
| 旧程序/本地资源 | 文件版本/哈希、key/行列、原始文献或生成链及核验范围 | 文件存在、矩阵有限或程序可运行不证明其科学来源 |

纯数学常量和未赋数值的积分变量无需伪造文献；物理常数必须注明标准来源与版本。
`Parameter ID`、`NPZ key`、`source_id`、`derived/constant` 和参考文献总表都不能单独代替具体出处。

## 2. 一条可用的证据链

```text
原始材料/数据版本 + 可打开位置 + 标准引用 + 文件指纹
  → 原文页/表/公式/行列/数组范围 + 提取值和单位 + 核验范围
  → P01 claim（直接提取、转录、数字化、推导或用户选择）
  → P03 字段/IR Parameter ID 或 resource key
  → output 中的具体参数行、公式、CSV列/行范围或 NPZ key/slice
```

- P00 独占书目、版本、路径/URL 和哈希。期刊论文写作者、题名、期刊、卷、页码或文章号、年份、DOI/arXiv 版本；数据发布写机构、数据集、release/版本、持久标识及访问日期；未发表笔记如实标明，不编造作者或出版信息。
- P01 每条 claim 指向**实际直接来源**，给出 PDF 页码与印刷页码（不同时分别写）、节/表/图/公式或文件行列；转引的上游来源单独引用，并说明是否读到原文数值。书目核验、原文数字核验和用户科学决定分开记录。
- 推导 claim 引用全部输入 claim 和推导方法。结果可沿有向无环依赖链回到原始输入或明确的配置决定；缺失/冲突/未核实状态必须传播，不能由“推导成功”洗成原文已核。
- 数据表可以按同来源的列/连续行范围登记，数组可以按 key/slice 登记，无需为百万行重复同一书目；不同来源或不同变换必须拆开映射，确保每个数值恰好有清楚的来源覆盖。
- 记录单位、坐标、观测语义、归一化因子及施加次数；原始数据、处理后的数据、配置选择和诊断对照明确区分。
- 没有依据时不填猜测值、零值或“常用值”。草稿保留缺失；对本次实际采用的数据不得留无法解释的来源空白。

## 3. 首次输出之后必须说明和交互

**首次生成 onboarding 的可读输出后，执行者必须立即完成一次来源与缺口说明，不能只给文件链接、PASS 或“已补齐”。**
尚未获写入授权时，在对话中展示同样的草稿与说明，不为满足本条擅自创建文件。

1. 输出标明版本/日期、dataset、目标和“首次草稿/待补充”；开头说明当前已取得什么、核到了哪一层。
2. 同时在对话和现有输出的“来源、限制与状态”中列出：缺什么、缺的是数据还是原文溯源、当前替代材料、影响什么、接下来如何补。实现审计/数值积分待办另列，不冒充实验缺数据。
3. 对影响目标的未决项提出具体、可回答的问题：需要哪份表/原文，是否允许沿已有引用继续查找，或在无法取得原数据时是否接受已明确说明的近似。先完成已授权的文献核查，不让用户重复提供可取得的信息。已有选择不重复询问。
4. 等待依赖该问题的答案；同时可处理不依赖它的工作。问题未答、用户选择暂缓或仍找不到原文时，保留缺口及受影响能力，不能将沉默当作确认。
5. 收到新材料/答复后，按其角色更新 P00/P01、P02 问题状态、决定引用及 P03/IR；原来未核实的证据不因用户表示接受而改成“原文已核”。
6. 重新生成所有受影响的 MD、配置和 data，复查数值/单位/来源覆盖；回复说明本轮补了什么、还有什么未闭合。重复有实际缺口的步骤，直到满足本次交付条件。

有缺口时采用这样的短表，不把内部 YAML 当作人类解释：

| 项目 | 已有数据与直接出处 | 尚缺的数据/原文定位 | 对目标的影响 | 补充办法及需要用户决定的内容 |
|---|---|---|---|---|
| 按本次真实缺口填写；没有缺口写“本次未发现待补项” |  |  |  |  |

如果首次输出已经完整溯源，明确说“本次目标所需的数据与来源未发现缺口”，给出核验范围，再进行已有的人类审阅；不制造额外的确认循环。

## 4. 每类 output 必须显示什么

这里的 output 指本次实际生成的文件，不要求迁移到字面名为 `output/` 的目录，也不为此改 Runtime 包布局。

| 输出 | 必须可见的标记 |
|---|---|
| `experiment.physics.md` | 参数值表有“直接出处及原文定位”“证据性质/核验范围”；每条实验公式旁有来源或推导说明；符号表可追到同页参数表或唯一来源索引；末尾有标准参考文献及未闭合项 |
| `experiment.physics.summary.md` | 状态/版本、主要输入的来源入口、尚缺数据与溯源缺口，以及详细版对应章节链接 |
| `EXPERIMENT_USER_INPUT.md` | H2 显示具体出处与核验范围；“未决问题”保留补充问答与结果，并引用权威记录 |
| 配置/YAML/IR | 每个实际参数/资源映射到既有来源/证据引用；派生值记录输入与推导；不在不同文件维护互相独立的来源身份 |
| CSV/NPZ/二进制数据 | CSV 用来源列或配套映射说明，NPZ 等用既有配置/元数据映射；精确到列/行范围/key/slice，并附单位、变换、原始版本和生成方法；不能只写“见论文” |
| 图与数值结果 | 图注/配套结果元数据说明输入版本、来源映射和处理方法；生成结果通过输入依赖链溯源，不伪称实验测量 |
| 数据目录 README/已有验收记录 | 文件用途、原始/派生/诊断性质、来源映射入口、检查范围、未核实项及适用限制 |

标准参考文献就近用可点击编号引用，条目集中维护；引用链必须能从所见数值出发查到，不能要求读者先从程序字段名猜是哪篇文章。
详细版采用项表至少能回答下列各列；同等信息可以分成相邻表格，但不得只保留程序位置：

| 数据/配置项 | 值与单位或数组范围 | 直接出处与页/表/式/文件定位 | 证据性质及实际核验范围 | 推导输入或决定引用 |
|---|---|---|---|---|
| 按实际采用项填写 |  |  |  |  |

修订生成内容时先改同源记录/生成器再重生成；不得只手改 MD 导致下次导出丢失来源。

### 在使用数据的章节展示来源和数值

Source、Target、Detector Response、Observable、Prediction folding 和 Statistics 各自提供输入表。读取该章即可判断每项输入的实际取得情况与用途。

| 输入或公式符号 | 实际数值或数组范围 | 单位与坐标 | 本地数值文件与行列或 key | 直接文献与精确定位 | 实际核验及适用性 | 缺失对下一步的影响 |
|---|---|---|---|---|---|---|
| 按实验实际输入填写 | 标量填值与误差。大数组填 shape、各轴、代表值及完整文件链接 | 记下每个因子的归属 | 链接直接指向取得的文件 | 本章附标准书目，定位页、表、图、式或原发布文件 | 区分数值已核、来源待核与版本适用性待核 | 按依赖能力填写 |

公式后的符号表增加“数值取得情况”和“数据与出处”列。积分变量、定义量、项目推导量和需要实测或校准的数值输入逐项说明。需要数值函数或分布而尚未取得时，值列写 MISSING，并列出所需材料、检索结果和被阻断的计算。

Detector Response 必须逐项检查概率核、光/电荷产额、增益及涨落、分辨率或迁移、效率与选取、bin edges、系统误差与相关性。使用已经包含选取的单能模板时，记下原文件名、原数组 key、axis 顺序、网格、选取归属和归一化范围。对仅有 Qy 均值、通用校准参数或不同年份模板的材料，分别记录它们能支持的计算和还需要的输入。

<a id="module-numerical-provenance"></a>

### 共享模块背后的数值资源

Nuclear Response、Source loader、Detector model 等模块必须展开到实际数值资源。核响应至少展示核素及版本、全部所用通道、矩阵基底及行列顺序、系数阶数或动量网格、指数因子、振子长度及单位、归一化和实际数值切片，并给出完整数组链接。源谱、探测器概率核按同样原则展开各自所需数组。

逐项记录数值文件是否取得、直接材料是否已读、上游原文是否已核、转换是否等价以及适用性是否确认。不同检查分别记录证据，不新增科学批准状态。已有本地数组而缺少原始转换链时，展示数组并写明来源未闭合；数组本身未取得时写 MISSING。仅有代码类名、文件格式名、零动量近似或相似的作者仓库不能证明该文件来自该版本。

作者原始数据、二手聚合表和项目生成表分别登记 source_id。系数变换、拟合、基底转换、单位和归一化必须给出算法、版本和逐项比较结果。上游对应关系未证实时，只能列为候选上游。将未闭合项沿 input_claims 传递到依赖它的事件数、拟合和 benchmark，在交接表保留阻断范围。

用户明确选择直接复用原项目data资源时，登记原文件及现有读取约定作为本次采用的直接来源，核对实际key、数值和单位。外部作者或生成链未核实的部分继续展示，仅限制依赖外部来源认证或原论文等价的主张，不额外阻断用户已选的原表复用。用户选择不将外部来源状态改为已核。

同节标准引文与参数行相互对应。文末书目和数据目录继续承担汇总、完整数组存储与跨文件导航的职责。报告正文展示实际采用的标量与小型逐箱数据，并给大型数组提供可回读的数值入口。

下一阶段交接表列出能力、必需输入、取得及核验状态、待补材料与实际可执行步骤。依赖 MISSING 或适用性待核项的能力继续保持待补状态。

必需输入按本次请求的观测维度和统计目标确定。一维预测可采用已核的边际响应，原生多维likelihood的额外分箱、形状及校准约束单独列入相应能力。可由完整模板求和或积分取得边际响应时，将轴范围、算法和结果回填同一P01/P03。

## 5. 终稿验收与不能越过的边界

交付前在已有 P05 或本次验收记录中逐项报告：

- 实际采用的标量、模型配置、物理常数、数组和处理规则的完整清单；每项有对应的输出位置与可解析的来源链。
- 无依据的采用项为零；悬空引用、缺失定位、未说明的变换或上游缺口不得隐藏。
- 本次需要原文数值核验的项目均有真实核对记录；仅找到 DOI、书目或引用它的其他文章不能通过这一项。
- 推导/数字化/近似被如实标注；逐数据覆盖可按表/范围检查，但不是仅检查参考文献数量。
- 机器结构/哈希/链接检查、执行者逐数据检查、原文核查和用户物理审阅分别报告，不互相替代。

首次草稿和后续候选允许明确保留 `MISSING/CONFLICT` 或来源未核实，但不能作为所请求主张的完成版。
若用户明确接受二手材料、数字化或近似，可以形成相应**范围的有据候选/近似终稿**；必须保留直接出处、未核实上游及决定，调整主张，不能宣布严格原文 benchmark 已复现。
如果依赖该数据的主张仍要求原文核验，则继续保持 PARTIAL/BLOCKED。
未请求能力的缺口继续记录，仅阻断依赖它的能力，不强迫补齐整套实验。

保留旧版本和来源快照，标明本版日期及变动；不得静默回写历史证据或将旧文件自动宣称符合新规范。

## 6. 现有工具与执行责任

本规范是 Master/Onboarding 和输出验收的强制执行要求。现有工具可检查 schema、引用存在、文件哈希、数组形状和同源生成一致性；
**没有通用工具自动认证原文真实、逐个参数的引文确实支持该数值，或自动读取 P00–P03 完成全部来源映射。**
生成器没有提供足够出处展示时，执行者必须记录该输出缺口，并在获准的生成链维护范围内补齐后重生成；不能靠一份参考文献总表宣布终稿合格。
本次规则更新本身不修改 Renderer/Schema、实验数据或历史输出；工程能力见[Compiler 说明](../../../../docs/software/onboarding-package-compiler.md)。
