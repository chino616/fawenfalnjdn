# 文件增减与 README 联动维护

本规则适用于整个仓库的文件新增、修改用途、删除、移动和重命名，包括普通代码维护、文档工作与实验接入。文件操作、所属 README、上级导航和实际注册/资源引用是同一次变更的组成部分；只完成文件操作不能视为任务完成。

## 文件由哪份 README 说明

每个正式目录由本目录 README 或最近的上级 README 说明其职责、主要文件和使用方式。新增一级、二级目录时补充该目录 README 并从上级导航链接；更深层的工具、数据表或内部模块可由所属目录按明确类别说明，无需给每个文件另建 README。

开始变更时，在计划或变更记录中对应下列信息：

| 文件操作与原路径 | 新路径或删除原因 | 所属 README | 受影响的上级索引/其他文档 | 程序、资源或工作流绑定 | 检查命令/结果 |
|---|---|---|---|---|---|
| 本次实际操作 | ____ | 明确路径或负责该类文件的说明 | ____ | ____ | ____ |

清单可以放在已有任务报告中。目录按类别介绍文件时，明确类别和消费者；未列举每个内部文件不等于遗漏，但每个新增文件都应能找到说明其用途的归属。

## 各种操作需要同步什么

| 操作 | 本次同步维护 |
|---|---|
| 新增文件 | 补充所属 README 的用途、读取/调用入口、必要参数和检查方式，或核对其已经被准确的类别说明覆盖；必要时更新上级导航与实际注册 |
| 删除文件 | 从当前说明、文件表、示例命令和导航中删除对应条目，或改指真实替代文件；清理当前消费者和清单中的失效引用 |
| 移动/重命名 | 更新原目录与新目录 README、相对链接、命令、上级索引及程序绑定；记录旧→新路径；只删除已经失效的旧入口 |
| 改变用途、接口或读取行为 | 更新说明中的用途、参数、输入输出与限制；文件名未变也要检查描述是否过期 |
| 新增/删除整个目录 | 同步父目录导航；新增正式一级、二级目录附 README；删除目录前确认当前内容与消费者已按授权处理 |

**删除文件时，通常删除 README 中对应的条目，不删除整份 README。** 目录仍有活动内容，就保留并修正其说明；只有整个目录明确被移除、没有需要保留的说明和当前消费者时，才在本次目录删除范围内移除该 README，并清理父级入口。

相对链接、反向引用、命令中的裸路径与代码中的 import/资源绑定分别核对；链接检查通过并不证明这些其他引用都已同步。

## “自动同步”的执行含义

执行者在每次文件变更任务中主动完成上述同步，不等待用户再提出“更新 README”。已授权普通工程任务内的配套说明维护随本次任务完成；正式物理接入仍按已有 scope 和准确路径授权执行，不能借 README 同步扩大数据、物理选择或写入范围。

当前仓库没有文件系统监听器，也没有自动理解并删除任意 README 段落的程序。检查器保持只读；文档同步由执行者实施并核验，不应声称“删文件就已自动改文档”。采用自动目录清单时，只更新明确标记的生成区域，保留人工说明与历史证据，避免整份覆盖。

批量变更可直接进入[仓库维护流程](../../cevns-pyeft/definitions/repository-maintenance/WORKFLOW.md)。
[readme_maintenance.py](../../../tools/readme_maintenance.py) 以 Git 提交或保存的快照生成目录分组计划；
`sync --readmes` 只改显式选定的 `readme-inventory` 标记区并保存备份，`check` 校验该区与当前文件系统及链接。
人工用途说明、未标记清单与旧路径残留仍按本规则核对，工具不自动提交 Git。

## 修改后怎样检查

1. 对照本次变更清单，逐项核对文件、所属 README、上级导航、引用和消费者；新增文件也必须核对其说明归属。
2. 对删除或改名的旧路径，在本次受影响的活动代码/文档范围内检查残留引用，分辨当前入口与应保留的历史说明。不要全盘扫描 backup 或把旧输出当作当前内容。
3. 检查受影响 README 和当前文档链接。可从仓库根目录执行：

   ```powershell
   python -B tools/validate_docs.py --files README.md tools/README.md workflows/README.md
   python -B tools/validate_docs.py --scope docs
   python -B workflows/cevns-pyeft/qa/validate_skill_pack.py
   ```

   `--files` 使用本次实际受影响的 Markdown 路径替换示例列表；它优先于 scope，只检查指定文件。Skill 结构检查只在相关流程/保护项变化时执行；数据资源变更再执行对应资源审计，算法变化运行相关测试。
4. 受保护 README 的获准修改只更新它自己的真实哈希；移动/删除登记准确的新旧路径。其他代码、数据、schema 和冻结参考的哈希不因文档维护而重新生成。
5. 完成报告列出文件操作、同步的 README/导航、实际检查结果与未解决项。仍有本次引入的失效引用或未说明的新文件时，不报告文件变更已完成。

链接工具能够发现删除后保留的失效链接，不能自动判断新文件是否写了足够说明、正文中裸路径是否正确、接口语义是否改变。新增项和描述完整性由上面的变更清单逐项核对；没有自动覆盖的检查如实记录。

## 当前说明和历史材料分开处理

[archive-isolation](archive-isolation.md) 与[数据目录规则](dataset-layout.md)继续适用。当前导航反映实际文件；历史报告、引用版本、冻结数组和旧数值证据按其当时状态保留，必要时在当前入口说明迁移关系，不静默重写历史以消除旧路径。

只在创建所需备份或明确恢复/审计时访问 backup。文档检查默认排除 backup、outputs、版本控制内部目录和缓存；除非用户明确要求，不修改生成产物与历史快照中的 README。

本规则只联动维护文档与绑定，不改变 Master 的唯一路由、科学批准、运行时隔离或实验激活条件。
